## Current blocker — guest agent transport / SSH routing

Guest Agent `file-write` for the 19,063-byte report **timed out** and left VM 151's agent unresponsive (a zero-byte temporary file was observed). Restarting the agent recovered it once. A subsequent 1,024-byte file write, 512-byte stdin test, and full **19 × 1,024-byte** report transfer succeeded. But an **8,192-byte `qm guest exec --pass-stdin`** test **also timed out** and again left the VM 151 guest agent **unresponsive**. At the last guest-console observation, `qemu-ga` PID 2558 still existed in `select`, but Proxmox `qm guest cmd 151 ping` did not respond; **no subsequent recovery has been confirmed**. The VM itself remained live and accessible through `qm terminal 151`.

Network: Proxmox host `vmbr1=10.151.0.1/24` → VM 151 `10.151.0.2`, `vmbr2=10.152.0.1/24` → VM 152 `10.152.0.2`. Routes exist, but host TCP/22 probes to both guests **timed out**, as did VM 151→152 SSH. `pve-firewall` is disabled/stopped and host `ip_forward=1`; **actual packet filtering and isolation have not been verified**.

Do not repeat large Guest Agent transfers or open VM-to-VM traffic indiscriminately.
